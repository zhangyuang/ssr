# Development Communication

We recommend that when you encounter problems, first carefully read this documentation to find solutions. If there's no record, or you still don't know how to solve it, you can submit an [issue](https://github.com/zhangyuang/ssr/issues) and we will reply as soon as possible.

Similarly, we have established communication groups to help developers get timely and effective responses. But please ensure that before speaking in the group, you have carefully read `The Art of Asking Questions` and [How to Submit Unanswerable Questions to Open Source Projects](https://zhuanlan.zhihu.com/p/25795393), and can provide a `minimal repository` that can reproduce the problem.

If you want to contribute to this project, please first read [CONTRIBUTING.md](https://github.com/zhangyuang/ssr/blob/dev/CONTRIBUTING.md) to learn how to debug source code locally. And ensure that when you want to submit a `feature` or `bugfix` type `PR`, you must communicate with official developers in advance through `issues` or `communication groups` before submitting. Otherwise, your `unauthorized` `PR` will most likely not be merged.
